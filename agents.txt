Step-by-Step: What Happens When You Ask a Question
STEP 1 — Input Sanitization (0ms)

Raw user input
    ↓
sanitize_user_input()
    • Remove null bytes
    • Collapse extra whitespace
    • Truncate if > 500 characters
    ↓
Clean query string
STEP 2 — Memory Resolution (0ms)

"Show me his deals"
    ↓
ChatMemory.resolve()
    • Looks at previous messages in this conversation
    • Resolves pronouns: "his" → "Ketul's"
    ↓
"Show me Ketul's deals"
STEP 3 — Guard Layer (0ms, NO LLM, NO DB)

5 instant checks — if any match → answer immediately, skip everything else:

  is_identity_question()   → "Who are you?" / "What is this?"
        ↓ answer: "I am the CRM AI Assistant..."

  is_greeting()            → "Hi", "Hello", "Good morning"
        ↓ answer: "Hello! I can help you query your CRM data..."

  is_blocked()             → DROP / DELETE / INSERT / UPDATE in query
        ↓ answer: "This query contains operations that are not permitted"

  is_system_config_query() → "SMTP config" / "file upload limit"
        ↓ answer: "This is stored in app config, not the CRM database"

  is_vague_query()         → query < 2 words with no entity/status keywords
        ↓ answer: "Your query is too vague, could you be more specific?"

If NONE match → continue to next step
STEP 4 — Fast Path (CURRENTLY DISABLED in your .env)

FAST_PATH_ENABLED=false  ← you disabled this

When enabled:
  • Regex + SQL templates, NO LLM, ~300ms
  • Handles ~70% of common queries instantly
  • 28 handlers: revenue, deals, tasks, KPI, pipeline, targets...

Since it's disabled → skip directly to classifier
STEP 5 — Classifier (Two Layers)

Query enters new 2-layer classifier:

┌─ LAYER 1: Pre-classifier (0ms, NO LLM) ─────────────────────────┐

Shared LLM Chain (Used by ALL Agents)

Every LLM call goes through llm_router.py:

  Task: "sql"       → Groq Scout-17b → Gemini flash-lite → OpenRouter DeepSeek → Ollama 7b
  Task: "classify"  → Groq 8b-instant → Gemini flash-lite → Ollama 3b
  Task: "narrate"   → Groq 8b-instant → Gemini flash-lite → Ollama 3b
  Task: "synthesize"→ Groq 70b → Gemini flash-lite → OpenRouter DeepSeek → Ollama 8b
  Task: "decompose" → Groq Scout-17b → Gemini flash-lite → OpenRouter → Ollama 8b

  Features:
    ✓ Per-key exponential backoff (respects retry-after header)
    ✓ 3 Groq API keys rotated to avoid rate limits
    ✓ SQL result cache (SHA-256, 5-min TTL, 200-entry LRU)
    ✓ temperature=0 for deterministic SQL output
